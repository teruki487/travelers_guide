## 管理方針

- マージ後のGitHub `main` ブランチを資料の正本とします。
- 資料の新規作成・編集は `docs/` 配下で行い、変更用ブランチを作成します。
- ブランチ名は `docs/<工程または変更内容>` とします。
- 各フェーズの資料が完成した段階でPull Requestを作成し、ユーザーにPR URLを渡して作業をいったん区切ります。
- PRには対象工程、変更概要、確認事項、検証内容、関連する要件IDを記載します。
- レビュー指摘への修正は同じPRのブランチへ追加します。
- ユーザーのレビューと明示的なマージ指示なしに、アシスタントはマージしません。自動マージも設定しません。
- 次フェーズはユーザーの進行指示後に開始します。
- 要件変更があれば、改訂履歴に理由と影響範囲を記載し、設計・実装・テストへの影響をPRで説明します。

## 公開範囲

このリポジトリは公開です。公開するのは開発資料と必要なソースです。実際の参加者情報、個人の旅行予定、認証情報、実データは登録しません。アプリ自体の公開範囲は、このリポジトリの公開設定とは別に管理します。

## 初回登録の範囲

要件定義書とレビュー運用、PRテンプレートのみを登録します。先行作成した設計案・画面試作は暫定のままで、このPRには含めません。
