## 2. 要件定義書

### 2.1 目的・確定要望

旅行に行くメンバーへ日程と持ち物を周知するWebアプリケーションをSitesで作成する。資料を作成しながらウォーターフォールを基盤として開発する。幹事が情報を一元管理し、参加者がスマートフォンから確認できることを目標とする。

### 2.2 初期版の仮定

- 小規模な友人・家族旅行を想定。日本語UI、オンライン利用、日付・時刻は旅行先の現地時刻として入力する（自動時差変換なし）。
- 幹事1名が編集し、参加者は閲覧と自分の持ち物チェックを行う。共同編集者・所有権移管は将来対応。
- ChatGPTアカウントを必要とするのはSites管理者のみ。旅行の作成・編集・閲覧には、ChatGPTを含むアカウント登録・ログインを要求しない。幹事・参加者の権限は専用リンクで区別する案とする。
- 本番では匿名アクセス可能な入口と、旅行単位の専用リンクによる認可を組み合わせる。旅行情報の変更を参加者へ自動通知し、開いている画面へリアルタイム反映する。本PRではSitesの公開設定変更や実際の通知送信は行わない。
- 初期検証目標: 1旅行30名、日程100件、持ち物100件、お知らせ30件。負荷試験完了値ではない。
- デスクトップとスマートフォンのChromeを対象とする。実機対応は受入試験で確認する。

### 2.3 機能・受入条件

|ID|要件|受入条件|
|---|---|---|
|FR-01|旅行作成・一覧・基本情報編集|タイトル、行先、開始日・終了日、集合案内を保存し再表示できる|
|FR-02|日程管理|幹事が日付・時刻・内容・場所・補足を追加・編集・削除でき、日時順に閲覧できる|
|FR-03|持ち物管理|幹事が名称と分類を編集でき、参加者は自身の準備状況のみ変更できる|
|FR-04|お知らせ|幹事が連絡文を追加・編集・削除し、参加者が閲覧できる|
|FR-05|アカウント不要の権限・メンバー管理|幹事が参加者用リンクを発行・失効でき、アカウントなしで参加できる。有効な権限を持たない者がAPIで読めない|
|FR-06|専用リンクによる共有|参加者用URLをコピーできる。幹事用リンクとの違いと、リンク所持者に権限が与えられることを説明する|
|FR-07|端末間保存|旅行内容と個人チェックをD1へ保存し再読込で復元する|
|FR-08|印刷・退避|ブラウザー印刷と旅行データJSON出力ができる（JSON復元は初期対象外）|
|FR-09|競合・エラー|旧版での上書きを409で拒否し、入力・通信エラーを画面表示する|
|FR-10|変更の自動通知|共有情報の変更をその旅行の有効な参加者へ自動通知する。画面内通知を必須とし、閉じている場合は許可済み対応端末にWeb Pushで通知する。未許可・非対応端末には次回表示時に未読を提示する|
|FR-11|リアルタイム同期|接続中の閲覧画面は手動更新なしで変更を反映する。切断中であることを示し、復帰時に欠落分を回復する。編集中の入力を自動上書きしない|

### 2.4 非機能要件

|ID|要件|検証方法|
|---|---|---|
|NFR-01|サーバー側の権限検証|アカウントの有無ではなく専用リンクから発行した権限を検証し、不正・期限切れ・失効・権限外の要求を拒否する。他人のチェックを更新できないことを確認|
|NFR-02|入力検証と安全表示|型・長さ・日付の検証、HTML文字列を文字として表示|
|NFR-03|レスポンシブ・操作性|狭幅で横スクロールなく主操作可能、ラベル・フォーカス・エラー通知を確認|
|NFR-04|実用上ストレスのない速度|想定規模の端末試験。測定前に性能保証しない|
|NFR-05|保守性|要求ID・設計・テスト対応、ソース管理、再配置可能な手順を残す|

### 2.5 対象外・未確定

予約・決済、外部経路API、天気連携、自動メール、チャット、画像添付、オフライン編集・保存同期、費用精算、JSON復元、自動バックアップ、旅行削除、管理監査ログは初期対象外。自動通知・リアルタイム同期・Web Pushは初期対象に変更する。旅行削除と参加解除時のデータ処理、保存期間、正式な参加人数・旅行数上限、費用許容額は正式運用前の確認事項。端末通知の許可は任意であり、通知許可なしでも編集・閲覧できる。


## 3. 要件定義フェーズの確認事項

PR #2のレビューで、アカウント不要と自動通知・リアルタイム同期はユーザーの指示として確定しました。以下は詳細化が必要な設計・運用事項です。

1. 専用リンクの有効期限・再発行・紛失時対応と、同じ参加者の別端末への引継ぎ方式。
2. 幹事1名のみ編集し、参加者は閲覧と自分の持ち物チェックを行う権限でよいか。
3. 端末を閉じている時のWeb Pushの許可案内、非対応時の表示、および通知・同期の性能目標。
4. 正式運用に向けた保存期間、旅行削除、バックアップ、費用の条件。

## 4. 次工程への引継ぎと現状

次工程は基本設計です。確定した要件と仮定の差分を整理してから、画面構成・権限・データ構造・共有方式へ落とし込みます。各工程の資料完成時に個別に出力し、工程ごとに区切ります。

先行作成した設計案と画面試作は暫定であり、本書の承認や本番実装完了を意味しません。現在の試作はブラウザー内保存のみで、サーバー保存・メンバー間同期・認証認可は未実装です。Sitesの新規登録は済んでいますが、公開完了は確認していません。
